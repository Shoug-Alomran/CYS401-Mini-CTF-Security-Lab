CRY-01 Easy 50 pts Unsolved

Base of Operations

A configuration file ships with a value the developer described as “encrypted”. It is a run of letters and digits ending in two equals signs.

Show hint

Those trailing equals signs are padding. This is an encoding with a well-known name, and every terminal and browser console can reverse it.

What this challenge taught you

Encoding converts data into another format for transport. It uses no key and protects nothing. Only encryption, with a key kept secret, provides confidentiality.

CRY-02 Easy 100 pts Unsolved

Caesar’s Message

An intercepted note reads as nonsense, but the word lengths and punctuation survive intact. Each letter has moved a fixed distance through the alphabet.

Show hint

There are only twenty-five possible shifts. Try them all, or count which letter appears most and assume it started as E.

What this challenge taught you

A shift cipher has a key space small enough to exhaust by hand. Modern algorithms are judged partly on key space, which is why key length matters as much as the algorithm.

CRY-03 Medium 150 pts Unsolved

The Reused Key

Two messages were encrypted with the same short key by XOR. You have both ciphertexts and know how one message begins.

Show hint

XOR the two ciphertexts together and the key cancels out, leaving the two plaintexts combined. The known opening gives you the rest.

What this challenge taught you

A one-time pad is unbreakable only if the key is truly random, as long as the message, and never reused. Reuse leaks the relationship between plaintexts, which is enough to recover both.

What You Take Away

Cryptographic failures in practice are almost never broken maths — they are broken usage.

  • Know what each tool provides

    Encryption gives confidentiality, hashing gives integrity, signatures give authenticity. They are not interchangeable.

  • Never roll your own

    Use reviewed libraries and current standards such as AES-GCM and SHA-256 rather than a scheme you invented.

  • Treat keys as the secret

    The algorithm is public by design. All the protection lives in the key, so how it is generated, stored, and rotated is the security.

  • Salt and stretch passwords

    Unsalted fast hashes fall to rainbow tables. Password storage needs a slow, salted function such as bcrypt or Argon2.
