Section 1

Introduction

Cybersecurity education covers both learning security concepts and applying them in practice. Capture-the-Flag (CTF) events offer a hands-on approach: learners analyze cybersecurity problems, identify security vulnerabilities, and solve them to obtain and submit flags. This lets learners use their cybersecurity knowledge in practical situations and builds critical thinking and problem-solving skills.

This project presents the design and implementation of a Mini Capture-the-Flag (CTF) Security Lab Platform that offers guided cybersecurity challenges based on fundamental security topics. The platform provides realistic security scenarios covering authentication flaws, insecure website and application configuration, phishing awareness, basic cryptography, and cybersecurity ethics.

Challenges are divided into four groups: Web Security, Cryptography, Security Awareness, and Cybersecurity Ethics. Users pick any challenge, read its scenario and objectives, solve the problem, and submit the flag they obtain. A scoreboard and completion status let users monitor their progress.

The main objective is an interactive, educational CTF security lab that lets users apply fundamental cybersecurity concepts through practical challenges, while strengthening security awareness, critical thinking, and CTF-style problem solving in a safe and controlled environment.

Section 2

Security Background and Analysis

A CTF lab holds things worth protecting: user identities, the flags that prove a challenge was solved, and the scores that rank participants. Identifying these assets, and the threats, vulnerabilities, and attacks against them, is the basis for the controls the platform needs.

2.1 Assets

Asset Description Security Importance
User Accounts Individual accounts used to identify users and associate their activity with the platform. Accounts must be protected from unauthorized access and impersonation so that activity and progress are associated with the correct user.
User Credentials Authentication information used to verify the identity of users when accessing their accounts. Credentials must remain confidential to prevent account compromise and unauthorized access to the platform.
Challenge Flags Secret values that users must discover and submit to complete CTF challenges. Flags must remain confidential until legitimately discovered. Exposed flags let users bypass the challenge and undermine the integrity of the CTF.
Challenge Content Security scenarios, instructions, hints, resources, and educational explanations for each challenge. Content must keep its integrity so challenges stay accurate, functional, and consistent with their learning objectives.
User Progress Records of challenges attempted and completed by each user. Progress data must remain accurate and protected from unauthorized modification so users receive the correct completion status.
Scoreboard Data Information used to represent participant scores, completed challenges, and rankings. Scoreboard data must keep its integrity to prevent manipulation of scores or rankings and ensure fair results.
Database The underlying storage for user, challenge, progress, and other application data. Unauthorized access, modification, or loss of database information could compromise the confidentiality, integrity, and availability of multiple platform assets.

2.2 Security Risks and Threats

Recognizing the risks that threaten users, content, the evaluation system, and platform data is crucial to choosing the right security controls.

Threat Description Affected Assets Potential Impact
Unauthorized Access An unauthorized individual attempts to access another user’s account or restricted areas of the platform. User Accounts, User Credentials, Database Account compromise, exposure of protected information, or unauthorized changes to user data and progress.
Credential Theft User authentication information is obtained through phishing or other credential-stealing techniques. User Credentials, User Accounts An attacker impersonates a legitimate user and gains unauthorized access to their account.
Flag Disclosure Challenge flags are exposed to users without them legitimately solving the challenge. Challenge Flags, Challenge Content Users submit exposed flags without completing challenges, reducing fairness and educational value.
Data Manipulation An unauthorized user alters stored completion records, scores, or challenge content. User Progress, Scoreboard Data, Challenge Content, Database Incorrect progress records, unfair rankings, altered challenges, and loss of data integrity.
Data Loss or Unavailability Platform data or services become unavailable through system failure, accidental deletion, or disruption. Database, User Progress, Challenge Content, User Accounts Users cannot access the platform, and stored progress or other information could be lost.
Malicious Input Users intentionally provide unexpected or malicious input through flag submissions or account forms. Database, Application, User Accounts Improperly handled input could affect application behavior, stored data, or platform security.

2.3 Vulnerabilities

A vulnerability is a flaw that an attack can exploit to cause harm. In the CTF Security Lab, vulnerabilities range across authentication, input processing, access control, data protection, and system configuration.

Vulnerability Affected Component Potential Consequence
Weak Authentication Controls User Authentication and Accounts Unauthorized individuals gain access to user accounts and impersonate legitimate users.
Improper Input Validation Flag Submission and User Input Forms Malicious or unexpected input affects application behavior or stored data.
Insufficient Access Control User Accounts, Progress Records, Scoreboard, Database Users access or modify information or functionality restricted to other users or administrators.
Insecure Flag Storage Challenge and Flag Validation System Users retrieve flags without solving the intended challenges.
Insecure Data Storage Database User information, progress records, challenge information, or other data is exposed to unauthorized parties.
Security Misconfiguration Web Application and Hosting Environment Incorrect permissions, exposed configuration, or insecure settings expose sensitive information or functionality.

2.4 Potential Attacks

The vulnerabilities above could be exploited through several attacks that compromise the confidentiality, integrity, or availability of platform assets. These four are the most relevant to the platform’s functionality.

Brute-Force Login Attack

Confidentiality · Integrity

An attacker repeatedly tries different username and password combinations to gain unauthorized access to a user’s account.

Target
User accounts and the authentication system.
Potential impact
Access to another user’s account, viewing or modifying their progress, and impersonating the legitimate user.

Injection Attack

Confidentiality · Integrity

An attacker submits specially crafted input through application fields to manipulate how the application processes data.

Target
Flag submission fields, authentication forms, other input fields, and the database.
Potential impact
Access to or modification of application data, interference with platform functionality, or compromise of stored information.

Broken Access Control

Confidentiality · Integrity

A user attempts to access restricted resources or perform actions reserved for another user or an administrator.

Target
User progress, scoreboard data, challenge management functions, and database records.
Potential impact
Modified scores, challenges falsely marked complete, access to another user’s information, or altered challenge content.

Denial-of-Service (DoS)

Availability

An attacker sends an excessive number of requests to consume resources and prevent legitimate users from reaching the service.

Target
The web application and hosting infrastructure.
Potential impact
The platform becomes slow or unavailable; users cannot open challenges, submit flags, or view progress.

Section 3

Literature Review

3.1 Capture-the-Flag in Cybersecurity Education

Capture the Flag (CTF) is an effective way to learn cybersecurity: participants complete challenges to find hidden flags, and each flag proves a challenge was solved. CTF lets participants apply security principles to problem-solving tasks in cryptography, web security, network security, and more.

CTF competitions are usually Jeopardy-style or Attack-Defense. Jeopardy-style CTFs consist of separate challenges grouped into categories; in Attack-Defense CTFs, teams exploit vulnerabilities in opposing systems while protecting their own infrastructure. The Mini CTF Security Lab follows the Jeopardy-style approach because it lets users complete individual educational challenges and track their progress.

CTF activities increasingly complement traditional cybersecurity education. Švábenský et al. (2021) analyzed 15,963 textual solutions to CTF challenges and found that CTFs offer real opportunities to gain practical cybersecurity knowledge, but that human-centric topics such as social engineering and security awareness receive comparatively little attention. CTF learning can also be hard for beginners and light on non-technical aspects of security.

The Mini CTF Security Lab addresses these gaps with an equal combination of technical and non-technical learning, including dedicated security awareness and ethical reasoning tracks.

3.2 Existing and Previous Solutions

Three existing platforms show different ways of organizing cybersecurity tasks for learning.

Carnegie Mellon University

picoCTF

An educational platform with interactive challenges and contests aimed mainly at students and novices, covering cryptography, web exploitation, and more. picoGym lets learners practise on challenges from past competitions, while picoCTF competitions run them in a competitive setting with increasingly difficult tasks.

Lesson for our lab

With so many technical challenges, users without a security background may need more guidance — so our lab gives every challenge clear instructions and a hint.

picoctf.org ↗

Open-source CTF framework

CTFd

Open-source software for running CTF competitions. Administrators create challenges, manage participants, and check flags and results. It supports challenge descriptions, downloadable files, hints, points, automated flag validation, a configurable scoreboard, plugins, and themes.

Lesson for our lab

CTFd is a framework: organizers must write all the challenges and educational content themselves. Our lab instead ships a small, guided set of challenges aligned with fundamental concepts.

docs.ctfd.io ↗

Wargames community

OverTheWire

A set of wargames teaching security through technical exercises: Bandit covers Linux command-line basics, Natas covers web security, and Krypton covers cryptography. Unlike separate CTF challenges, it uses levels, where solving one level yields what you need for the next.

Lesson for our lab

Heavy reliance on command-line tools can be hard for people unfamiliar with Linux; our lab is web-based and solved entirely through a graphical interface.

overthewire.org/wargames ↗

Section 4

Proposed CTF Security Lab Platform

4.1 Project Objectives

Main objective

To design and implement a secure, web-based Mini Capture-The-Flag (CTF) Security Lab Platform that delivers guided, hands-on cybersecurity challenges across both technical and non-technical domains, reinforcing fundamental cybersecurity principles in a controlled educational environment.

  1. 01

    Diversify challenge categories

    Create 8–12 guided CTF challenges covering all four categories: Web Security, Cryptography, Security Awareness, and Cybersecurity Ethics.

  2. 02

    Automate flag validation

    Validate submitted flags automatically against hashes stored safely in the system.

  3. 03

    Hints and explanations

    Give a hint that helps the user while solving, and an explanation of the concept once the challenge is solved.

  4. 04

    Track progress and points

    Calculate the points each user earns and show them on a user progress section and a live leaderboard.

  5. 05

    Platform security controls

    Apply application-layer controls such as salted password hashing, input validation, and session-based access control to prevent SQL injection and flag leakage.

  6. 06

    Intuitive user experience

    A simple web-based graphical interface, so users solve problems without needing a command line.

4.2 Functional Requirements

ID Module / Feature Requirement
FR-01 User Authentication The system shall allow users to register an account, securely log in using username/password, and manage active sessions.
FR-02 Challenge Listing The system shall display all available challenges categorized by domain (Web, Cryptography, Awareness, Ethics) alongside their difficulty levels and point values.
FR-03 Challenge Execution The system shall display scenario descriptions, target environment details, instructions, and flag submission fields upon selecting a challenge.
FR-04 Automated Flag Validation The system shall accept flag inputs, evaluate them against stored secret hashes, and display immediate visual confirmation (Success / Incorrect).
FR-05 Hints and Explanations The system shall provide unlockable hints during challenge attempts and reveal detailed post-completion explanations reinforcing cybersecurity principles.
FR-06 Progress Tracking The system shall track individual user progress: solved challenges, completion percentages, and timestamps.
FR-07 Scoreboard & Leaderboard The system shall compute total points earned by each user and maintain an updated public scoreboard ranking all participants.
FR-08 Access Control & Roles The system shall enforce role-based access control (User vs. Admin) to restrict challenge editing and administrative configuration to authorized users.

4.3 Non-Functional Requirements

ID Requirement Description
NFR-01 Usability The interface shall be intuitive and responsive, letting users reach any challenge within three clicks from the main dashboard.
NFR-02 Security Stored passwords and secret challenge flags must be hashed with secure algorithms (e.g. bcrypt / SHA-256). Input fields must sanitize user input to prevent SQL injection and cross-site scripting (XSS).
NFR-03 Performance Page load times under 2 seconds, and flag validation requests processed in under 500 milliseconds under normal operation.
NFR-04 Reliability 99% operational uptime during active lab sessions, with no loss of user progress state in the database.
NFR-05 Compatibility Works across modern, standards-compliant browsers (Chrome, Firefox, Edge, Safari) without third-party plugins.

Section 9

Conclusion

The project develops a web-based Mini CTF Security Lab Platform that bridges the gap between cybersecurity theory and practice. Recognizing that non-technical cybersecurity concepts are often neglected in CTF education, the platform offers a well-rounded curriculum through Web Security, Cryptography, Security Awareness, and Cybersecurity Ethics challenges.

Its key elements — automatic flag validation, the hint and explanation module, the progress tracker, and the leaderboard — work together so users can learn at their own pace with timely feedback.

Through system integration and functional and security testing, the application demonstrates the key information security concepts covered in CYS401. Access controls, salted cryptographic hashing for passwords and flags, and input sanitization are built into the platform architecture to guard against injection attacks, broken access control, and unauthorized data disclosure.

Overall, the Mini CTF Security Lab Platform provides a scalable, secure, and user-friendly environment for university students and cybersecurity beginners. Future enhancements such as team-based competition modes, dynamic point decay, and expanded network defense scenarios would further strengthen it as a tool for cybersecurity training and academic instruction.
