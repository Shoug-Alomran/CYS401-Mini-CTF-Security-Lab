WEB-01 Easy 50 pts Unsolved

Hidden in Plain Sight

The login page for a small company portal looks ordinary. A developer left a note to themselves somewhere the browser does not display, and it contains the flag.

Draft lab · placeholder content

A simulated staff portal. Inspect it the way an attacker would.

Lab coming soon.

Show hint

Nothing here needs an exploit. View the page source, then check the files a site exposes by habit — robots.txt and old backups.

What this challenge taught you

Anything sent to the browser is readable by the user, including HTML comments, JavaScript, and files left in the web root. Secrets belong on the server, never in client-side code.

WEB-02 Easy 75 pts Unsolved

Guest Access

You log in with a guest account and reach a limited dashboard. The application decides what you may see from a value it stores in your browser.

Draft lab · placeholder content

A simulated guest dashboard that trusts a value stored in your browser.

Lab coming soon.

Show hint

Open your browser’s storage inspector and look at the cookies for the site. One of them describes who the application thinks you are.

What this challenge taught you

Authorization decided from client-side values is no authorization at all, because the client controls them. Roles and permissions have to be checked on the server against the session.

WEB-03 Medium 100 pts Unsolved

The Quotation Mark

The staff login form builds its database query by pasting your username straight into a string. Get in without knowing a password.

Draft lab · placeholder content

A simulated staff login whose query is built by pasting in your input.

Lab coming soon.

Show hint

Think about what a single quote does to a query that was not expecting one, and what happens when the condition after it is always true.

What this challenge taught you

SQL injection happens when input becomes part of the query rather than data within it. Parameterized queries, or prepared statements, keep the two separate and shut the whole class of attack down.

WEB-04 Hard 125 pts Unsolved

Leaky Endpoint

The portal loads your profile from an API call that names your account number. Another user’s record holds the flag.

Draft lab · placeholder content

A simulated profile page that loads records by account number.

Lab coming soon.

Show hint

Watch the network requests the page makes while it loads your profile, then ask what stops you requesting a different identifier.

What this challenge taught you

This is an insecure direct object reference: the server trusts the identifier the client sends without checking that this user may read that record. Every request needs an ownership check, not just a valid session.
